# การใช้งานหลังปรับสิทธิ์ระบบ

- เว็บไซต์เช็คแต้มต้องเข้าสู่ระบบ LINE และอ่านข้อมูลบัญชีที่ผูกไว้เท่านั้น
- ผู้ใช้ใหม่ส่งคำขอผูกบัญชี เจ้าหน้าที่ตรวจตัวตนก่อนอนุมัติจากหน้าแอดมิน
- เปิดหน้าตู้ด้วยบัญชี LINE ที่มี `is_council_member` แล้วเชื่อมต่ออุปกรณ์ USB Serial
- เฉพาะแอดมินเดิม (รหัส 32650 และมีสถานะสภานักเรียนในฐานข้อมูล) จัดการรางวัล แต้ม และคำขอผูกบัญชีได้
- ถ้าบันทึกแต้มล้มเหลวหรือยังยืนยันผลไม่ได้ หน้าตู้จะไม่แสดงรับแต้มสำเร็จ

## การตรวจสิทธิ์

`secure_api` ตรวจ ID token กับ LINE และตรวจ audience, issuer และวันหมดอายุก่อนประมวลผล
ฟังก์ชันประมวลผลอยู่ใน schema `recycle_private` ซึ่ง client เรียกโดยตรงไม่ได้
ตารางหลักเปิด RLS และปิดการเข้าถึงโดยตรงจาก `anon`, `authenticated` และ `service_role`
คำขอฝากใช้ UUID ของรอบฝากเดิม เพื่อป้องกันการเพิ่มแต้มและประวัติซ้ำ
การแลกรางวัลล็อกแถวนักเรียนและรางวัลใน transaction ก่อนตัดแต้มและ stock

## การทดสอบ

- `node --test tests/*.test.js`
- `npm --prefix kiosk-ui run lint`
- `npm --prefix kiosk-ui run build`
- SQL Editor: `supabase/security-regression.sql` ทดสอบสิทธิ์และรอบฝากซ้ำด้วยข้อมูลชั่วคราว แล้ว rollback

## งานที่เจ้าของบัญชีต้องทำ

ยกเลิก/หมุนคีย์ legacy `service_role` ที่เคยเผยแพร่จากหน้า API Keys ของ Supabase
การลบคีย์ออกจากไฟล์หรือปิดสิทธิ์ตารางไม่ได้ยกเลิกคีย์เก่า และคีย์อาจยังใช้กับบริการอื่นในโปรเจกต์ได้
หลังหมุนคีย์ ให้ทดสอบล็อกอิน LINE ด้วยบัญชีจริง และทดสอบการหยอดจากอุปกรณ์จริง
